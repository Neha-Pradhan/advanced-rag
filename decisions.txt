D4 · Why RAG at all (NCERT is public + LLMs search)
Options: bare LLM / LLM + web search / RAG
Choice: RAG
Why: need grounding in a specific edition, chapter/section attribution, enforceable
grade≤N boundary, honest "not in corpus" state. Knowledge availability was never
the problem; control and attribution are. NCERT is a stand-in for private corpora.

D5 · Chunking: section-aware
Options: fixed-size / paragraph / section-aware / semantic / agentic
Choice: section-aware on NCERT "N.N Title" headings; oversized sections sub-split
with overlap, heading prepended to every sub-chunk
Why: corpus has explicit author-made structure — use it. Semantic/agentic chunking
is for unstructured blobs. Small-to-big noted as Phase 6 experiment candidate.

D6 · One Qdrant collection, grade in payload
Options: collection-per-grade vs single collection + payload filter
Choice: single collection
Why: core query (grade ≤ N) spans grades — one filtered search vs multi-search +
manual score merging. Payload filtering exists precisely for this.

D7 · Embedding model: start MiniLM, swap = experiment
Options: all-MiniLM-L6-v2 (256 tok) vs 512-token class (bge-small/e5-small)
Choice: MiniLM baseline; chunker enforces token budget so truncation is impossible
by construction. Model swap runs later as a RAGAS before/after experiment.
Why: known ground, free, local; measure instead of arguing leaderboards.

D8 · Figures: full extraction + UI display (promoted from stretch)
Options: captions-only / extract images + vision descriptions + display / multimodal embeddings
Choice: middle path — extract images at ingestion, store path + description in
payload, Streamlit shows figure next to answer
Why: education bot without diagrams is half a product; deterministic (no LLM memory).

D9 · Hybrid search added to Phase 6 (not baseline)
Options: dense-only baseline / hybrid from day one
Choice: dense baseline, hybrid (BM25-family sparse + dense fusion, Qdrant-native)
as measured technique
Why: exact-term queries ("photosynthesis") reward keyword scoring; but adding it
unmeasured would break the before/after story.

D13 · Chunking rule (baseline)
Section-aware on NCERT "N.N Title" headings = base unit. Sections within 256-token
budget → 1 chunk. Oversized sections → sub-split on SENTENCE BOUNDARIES (never
mid-sentence) with small token overlap; heading prepended to every sub-chunk.
Token budget measured with MiniLM's own tokenizer (tokens, not words/chars);
real text budget = 256 − heading tokens − safety margin.
Why sentence-boundary over hard-cut: mid-sentence cuts smear the chunk embedding
(harder to retrieve the right chunk) and can fracture a fact across chunks. Effect
is a quality nudge not correctness-critical, but cheap to do right at this scale.
Rejected: LLM-summarize-long-chunks (throws away detail RAG needs) — parked as
small-to-big / parent-doc candidate for Phase 6.
